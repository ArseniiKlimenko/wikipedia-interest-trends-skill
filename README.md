# Wikipedia Interest Trends — Agent Skill

Самостійна навичка у форматі [Agent Skills](https://agentskills.io/specification) для засновників
B2C-продуктів. Вона використовує Wikimedia Pageviews, щоб оцінити, які теми набирають або
втрачають інтерес, порівняти мовні розділи Wikipedia, побудувати графіки та сформувати
односторінковий PDF-звіт із припущеннями й обмеженнями.

Основний артефакт — [`wikipedia-interest-trends/`](wikipedia-interest-trends/):

- [`SKILL.md`](wikipedia-interest-trends/SKILL.md) — інструкції Agent Skill;
- [`scripts/`](wikipedia-interest-trends/scripts/) — власний Python-код для API, статистики,
  графіків, перевірки тверджень і PDF;
- [`references/`](wikipedia-interest-trends/references/) — методологія, вибір статей і другі сигнали;
- [`tests/`](wikipedia-interest-trends/tests/) — 64 офлайн-тести;
- [`evals/evals.json`](wikipedia-interest-trends/evals/evals.json) — реалістичні запити й критерії;
- [`wikipedia-interest-trends.skill`](wikipedia-interest-trends.skill) — готовий пакет v1.2.0.
- [`LICENSE`](LICENSE) — ліцензія MIT; дані Wikimedia/Wikidata мають ліцензію CC0.

Детальна архітектура, пояснення статистики, усі команди та історія ітерацій описані у
[`wikipedia-interest-trends/README.md`](wikipedia-interest-trends/README.md).

## Що реалізовано

- пошук відповідних статей через Wikidata та перевірка мовного покриття;
- автоматичні тематичні кошики для широких тем;
- завантаження й місячне кешування Wikimedia Pageviews;
- відносне зростання, 95% інтервали, приглушення сплесків і оцінка довіри;
- порівняння мов/тем, настроюваний рейтинг перспективності та повторні запити;
- сезонність, 12-місячний прогноз, точки зміни й часткове об'єднання шумних оцінок;
- пошук тем, що ростуть, із BH-FDR та відокремленням сталого росту від новинних сплесків;
- Google Trends і App Store як додаткові, не основні сигнали;
- PNG-графіки, CSV/JSON і PDF на одну сторінку;
- claim check, який звіряє відсотки, знак, напрям і рівень довіри з розрахунками.

## Відтворення

Потрібні Python 3.9+ та інтернет. Перший запуск створює приватне віртуальне середовище із
закріпленими залежностями.

```bash
cd wikipedia-interest-trends
export WIKITRENDS_CONTACT="you@example.com"
python3 scripts/wt.py check
python3 scripts/wt.py selftest
python3 scripts/wt.py resolve "intermittent fasting" --langs pl,cs
python3 scripts/wt.py analyze \
  --topic "Intermittent fasting=Q1666254" \
  --langs pl,cs --months 24 --report-lang uk --out out/intermittent-fasting
python3 scripts/wt.py report out/intermittent-fasting
```

Вихід: `summary.md`, `analysis.json`, `data.csv`, три PNG-графіки, `narrative.md` і
`report.pdf`. Звіт створюється лише з повних місяців; перегляди Wikipedia трактуються як сигнал
цікавості, а не як готовність платити.

## Перевірені заміри

Фінальний submission QA виконано 27 вересня 2026 року на macOS ARM. Час залежить від мережі та
стану кешу, тому нижче наведено фактичні заміри, а не обіцяну швидкість.

| Перевірка | Результат | Фактичний замір |
|---|---:|---:|
| Офіційний `skills-ref validate` | PASS | `Valid skill` |
| Чисте середовище, Python 3.9 | PASS | 64/64 тести, 19,3 с |
| Чисте середовище, Python 3.12 | PASS | 64/64 тести, 16,9 с |
| Розпакований фінальний `.skill` | PASS | 64/64 тести, 8,4 с із готовим venv |
| Доступ до Wikimedia API | PASS | відповідь API отримано |
| Наскрізний `resolve → analyze → report` | PASS | PDF A4, рівно 1 сторінка |
| Чистота пакета | PASS | 30 файлів / 35 записів архіву; без `.pyc`, кешів, eval-відповідей і runtime-output |

Контрольний live-сценарій — інтервальне голодування у `pl.wikipedia` та `cs.wikipedia`:

- у польськомовному розділі немає окремої статті — це подано як прогалину, а не замінено іншим поняттям;
- для чеськомовного розділу: відносна зміна `−34% [−53%; −5%]`, довіра MEDIUM;
- незалежний перерахунок із CSV: сирі перегляди `−53,6%`, після приглушення сплесків `−42,0%`,
  відносний інтерес `−33,69%`; значення збігаються з `analysis.json`.

### Оцінювання на Claude Haiku 4.5

Навичку перевірено на трьох запитах із завдання, уточнювальному запиті та додаткових складніших
сценаріях. Порівнювались прогони з навичкою і без неї; відповіді оцінювались за наперед заданими
assertions, автоматичною перевіркою PDF/мови та ручним читанням. Артефакти лежать у
[`wikipedia-interest-trends-workspace/`](wikipedia-interest-trends-workspace/).

| Ітерації | З навичкою | Без навички | Час, с (з / без) | Токени, тис. (з / без) |
|---|---:|---:|---:|---:|
| 1–2, базові запити | 90–92% | 57% | 123–126 / 212–241 | 55–59 / 63–73 |
| 3–5, рейтинг і follow-up | 90–94% | 50% | 126–156 / 265 | 60–66 / 84 |
| 6–7, складні сценарії | 41/41 assertions | не запускався | 141–152 | 59–61 |

Без навички дешеві моделі обирали хибні статті, називали інше поняття польським відповідником,
рахували «зростання» як останній тиждень проти першого, не давали інтервалів і створювали
двосторінкові звіти. Виявлені помилки перетворювались на правила, кодові перевірки й нові eval-и.

## Обмеження

- Wikipedia вимірює цікавість, а не платоспроможний попит.
- Статті та тематичні кошики є проксі; їхній склад потрібно називати у звіті.
- Мовний розділ Wikipedia не дорівнює країні.
- Google Trends використовує неофіційний веб-ендпоінт; безпечніша альтернатива — CSV-експорт.
- Claim check ловить числові й частину мовних суперечностей, але не замінює ручну перевірку причинних
  або продуктових висновків агента.

## План розвитку

1. **Посилити eval-набір:** 20+ запитів, кілька прогонів на дешевих моделях, окремі критерії проти
   вигаданих причин, ринкових фактів і трактування пропозиції App Store як попиту.
2. **Зберегти відтворювані дослідження:** YAML-специфікація тем, мов, кошиків і ваг; повторний
   місячний запуск та алерти про зміну тренду.
3. **Масштабувати дані:** для сотень і тисяч статей перейти з per-article API на
   `pageview_complete`, DuckDB і Parquet; додати відновлювані фонові завантаження.
4. **Розширити статистику:** довша історія, кращий контроль невиявлених ботів, mobile-app як
   окремий сигнал, калібрування прогнозів на більшій вибірці.
5. **Посилити тріангуляцію:** офіційний Google Trends API, Google Play, Wikimedia unique devices
   та інші незалежні джерела з явними вагами й перевіркою узгодженості.
6. **Покращити продуктову форму:** інтерактивний HTML-звіт, більше мов звіту й сумісна міграція
   збережених результатів між версіями навички.

## Формат здачі

Кейс подається як посилання на **публічний GitHub-репозиторій**. У репозиторії мають залишитися
вихідний код навички, `SKILL.md`, залежності, тести, методологія, цей README та достатні докази
AI-оцінювання. Секрети, локальні venv, кеші, `__pycache__` і робочі результати користувачів не
публікуються.
